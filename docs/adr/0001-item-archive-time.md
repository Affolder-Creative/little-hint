# Record item archive time separately from list order

Archived-item browsing follows the latest individual archive action, so record archive time independently of creation time and retain the item's manual list position for restoration. Restoring an item and archiving it again starts a new archive time; ordinary edits do not. Whole-list and event archiving retain their existing ordering and do not count as individual archive actions.

Existing archived items have no recoverable archive time. Keep that history unknown and place these items after timestamped archives in their existing default relative order. Assigning creation or rollout dates would invent a chronology that the stored records cannot support.

The agreed browsing behavior and acceptance criteria are tracked in [issue #216](https://github.com/Affolder-Creative/little-hint/issues/216).
