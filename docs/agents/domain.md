# Domain docs

This repository uses a single-context layout:
- `GLOSSARY.md` at the repository root defines domain terms.
- `docs/adr/` holds architectural decision records.

## Before exploring

Read `GLOSSARY.md` and the ADRs relevant to the area being changed.

If these files are absent, proceed silently. The domain-modeling
skill creates them as terms or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
Follow any explicit guidance about synonyms.

When a needed concept is missing, check whether an existing term
covers it. Record genuine gaps for domain-modeling.

## Decision conflicts

Explicitly identify any proposal that contradicts an existing ADR.
Name the ADR and explain why the decision should be reconsidered.
